Blora Design BBBS 已解决

把 BBBS 页面迁到 Blora Design 2.0 的一些记录

Lo
Loong

发布于 12 分钟前 · 浙江 · 最后编辑于 5 分钟前

这两天把 BBBS 的 Today 与帖子详情页整理成了一个只依赖 Blora Design 2.0 公开发布面的静态版本。目标不是重新设计论坛，而是保留原来那种左侧常驻导航、内容密集的推荐流和直接进入讨论的阅读节奏。

这次实际复用了什么

页面骨架使用 Sidebar Layout，导航使用 Sidebar Navigation，搜索框、主题切换和评论区都由正式 Custom Elements 承担。帖子列表继续使用开放的 Card、List、Avatar、Tag、Badge 与 Button 样式，因此业务内容和 DOM 仍然由站点自己掌握。

  • 桌面侧栏保持粘性，窄屏时由 Layout 自动切换成抽屉。
  • Today 保留日期、AI 摘要、快速发帖和推荐理由。
  • 帖子页保留作者信息、正文、标签、浏览与回复统计。
  • 评论使用 Thread add-on，长评论可以展开和收起。

第三方接入时最需要注意的点

Composite Custom Element 不应该由业务手写内部结构；图标也不应直接塞字符，而是通过公开的 createBloraIcon() 创建。页面自己的布局尺寸可以正常写 CSS，但颜色、阴影、圆角与动效应继续使用 Blora token，这样主题和深色模式才能一起工作。

这份页面是消费侧示例，不依赖 packages/blora-design/src，也没有复制任何组件内部实现。

我试了一下评论折叠。短评论不会出现多余按钮，长评论才会折叠，这一点比业务自己按字符数猜测更可靠。

不过当前 Thread add-on 只负责评论卡片与 composer 外壳，楼中楼的数据组织、评论排序、引用目标和提交请求仍然要由论坛业务实现。

对 BBBS 这种已经有完整评论模型的项目来说，这其实比较合适：可以继续沿用现有接口，只把呈现和基础交互交给公开组件。

如果以后需要更深的楼中楼视觉层级，最好由 add-on 增加正式 contract，而不是消费侧依赖内部 class 做缩进。
